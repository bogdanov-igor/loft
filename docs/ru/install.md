# Установка и обновление

## Требования

- [Claude Code](https://claude.com/claude-code)
- `bash`, `tar` — на macOS и Linux есть из коробки
- `python3` — все скрипты ядра только на stdlib
- Опционально `pandoc` — скиллам `ingest-confluence`, `ingest-docs`,
  `review-intake`, `deliver-pdf`; `lxml` — только `ingest-confluence`

Больше ничего: ни MCP-сервера, ни демона, ни индекса, который надо собирать.

## Быстрый старт

**1.** Скачайте `loft_1.3.3.tgz` и `loft_1.3.3.tgz.sha256` из
[Releases](https://github.com/bogdanov-igor/loft/releases/latest) в папку
проекта.

**2.** Откройте проект в Claude Code и скажите:

> Установи loft из архива в этой папке: сверь sha256, распакуй, запусти
> `loft/install.sh` и расскажи, что появилось.

**3.** Жил под specos — добавьте «почисти остатки specos и предложи
переаудит»: машинерия уедет в карантин, ничего не потеряв, см.
[миграцию](migration.md).

## Руками

Оба пути запускают один и тот же инсталлер.

### Из архива

```sh
cd /path/to/project                 # оба файла скопированы сюда
shasum -c loft_1.3.3.tgz.sha256     # сначала целостность: ждём "OK"
tar -xzf loft_1.3.3.tgz
bash loft/install.sh                # без аргумента = ставим в этот каталог
```

Папку `loft/` можно оставить в проекте (её увидит проверка обновлений, а
повторный запуск `install.sh` обновит ядро) или удалить. Оставляете —
добавьте `loft/` и `.tgz` в `.gitignore`.

### Из репозитория-исходника

```sh
git clone https://github.com/bogdanov-igor/loft.git
bash loft/install.sh /path/to/project
```

## Что делает инсталлер

| Действие | Детали |
|---|---|
| Ставит ядро | Копирует `bundle/.claude` настоящим каталогом, никогда симлинком — симлинки ломают резолв путей хуков и пер-проектность. Существующий `.claude` сначала уходит в `.claude.bak.<timestamp>`; два запуска в одну секунду получают разные имена бэкапов, чтобы новый не лёг внутрь старого. Всем `*.sh` внутри нового `.claude` проставляется бит исполнения: архиватор и копирование его теряют, а хукам и `sweep.sh` он нужен сразу. |
| Штампует версию | Пишет `.claude/VERSION` — его читает проверка обновлений. |
| Сохраняет ваши скиллы и агентов | Каталоги скиллов и файлы агентов, которых ядро не поставляет, переносятся из прежнего `.claude`. Исключение — specos-managed `.claude`: его собственные скиллы и агенты опознаются по wire-спискам specos и остаются в бэкапе, чтобы машинерия предшественника не вернулась с переустановкой. |
| Сохраняет вашу настройку Claude Code | Возвращает из бэкапа `settings.local.json` (разрешения), `commands/`, `rules/` и ваши собственные output-styles — пофайлово, потому что `output-styles/analyst.md` поставляет ядро. specos-овские `commands/` и `rules/` проектными не считаются и остаются в бэкапе. |
| Сеет состояние проекта | Создаёт `memory/` (с `lessons/antipatterns/patterns/structures`), `stages/`, `spec/`, `spec/_reference/`, `spec/_reviews/`, `inbox/`, `inbox/done/`, `BACKLOG.md`, `QUESTIONS.md`, `memory/MEMORY.md`, `spec/_STRUCTURE.md` (профиль с готовой секцией «Голос») — только там, где их нет. Существующее состояние не перезаписывается. |
| Защищает секреты | Добавляет `.secrets.env` в `.gitignore`. Файл без завершающего перевода строки сначала дописывается им, иначе последний паттерн склеился бы с новым. |
| Сеет граф корпуса | Создаёт `.vscode/extensions.json` с рекомендацией Foam и mermaid-превью — граф и обратные ссылки в VS Code одним кликом. Только если файла рекомендаций ещё нет. |
| Убирает MCP-налог | specos'овский `.mcp.json` (serena + playwright + memory ≈ 20–30k токенов схем на сессию) уводится в бэкап; свои серверы, если были, вы возвращаете руками. specos'овским считается конфиг, где specos'овский сам сервер — имя или путь запуска, а не любое упоминание слова в комментарии. Любой другой `.mcp.json` остаётся как есть, с напоминанием: каждый сервер стоит токенов схем в каждой сессии. |
| Детектит наследие | Гоняет миграционный sweep в режиме превью и сообщает о машинерии specos/skillforge, указывая на скилл `migrate-specos`. Сам ничего не переносит. |
| Самопроверяется | Проверяет, что контракт на месте, хуки исполняемые, число скиллов сходится и `link_check` реально отрабатывает. Провалившись, откатывает установку: неудачное ядро удаляется, прежний `.claude` возвращается из бэкапа — полуустановленное ядро на месте рабочего хуже несостоявшегося обновления. |

### Output style

Ядро кладёт `.claude/output-styles/analyst.md`, но по умолчанию его не
включает. Стиль снимает установки Claude Code про написание кода:
инструменты ядра запускаются как есть, скрипты не улучшаются на ходу,
сломанный инструмент — находка для владельца, а не задача на правку.
Включается через `/config` → Output style → `analyst`.

## Обновление

Самый простой путь: скачать новый архив в папку проекта и сказать:

> Обнови loft из архива в этой папке.

Руками — та же команда, что и установка, из более новой папки loft (свежий
релиз или `git pull`):

```sh
cd /path/to/project
bash loft/install.sh
```

Файлы ядра заменяются. Состояние проекта — wiki, ТЗ, память, стейджи,
бэклог, вопросы, ваши скиллы, агенты и настройки Claude Code — не трогается.
Старые бэкапы `.claude.bak.*` можно спокойно удалять.

### Как вы узнаёте об обновлении

Хук на `SessionStart` сравнивает `.claude/VERSION` с дистрибутивом рядом
(папка `loft/` в проекте или `$LOFT_HOME`) и с последним [релизом на
GitHub](https://github.com/bogdanov-igor/loft/releases). Что-то строго новее
— одна строка; версия актуальна — ни строки, и обычный случай стоит ноль
токенов.

GitHub-запрос кэшируется на 24 часа при удачном ответе и на час при
неудачном — старт сессии в поезде или за фаерволом не должен стоить трёх
секунд каждый раз — и упирается в жёсткий потолок 3 секунды. Без
`XDG_CACHE_HOME` и `HOME` кэшу негде жить: проверка релизов пропускается,
локальные источники работают дальше. Любой сбой — тихий выход, заблокировать
сессию проверка не может. Полное отключение: `LOFT_NO_UPDATE_CHECK=1`.

## Сборка архива (мейнтейнерам)

```sh
bash build-archive.sh    # → dist/loft_<version>.tgz + .sha256
```

Сам `build-archive.sh` в архив не кладётся. Сначала он прогоняет
`test/run.sh` — более 500 самотестов скриптов ядра, офлайн, на одноразовых
фикстурах — и отказывается собирать, если хоть что-то упало. Затем
распаковывает собранный архив во временный каталог и делает настоящую
установку, проверяя результат от начала до конца. Сборка герметична: свой
кэш вместо настоящего `~/.cache` и никакой сети.

Упаковывает архив не системный `tar`, а `python3` (`tarfile` + `gzip`):
формат ustar, записи в порядке байтов пути, uid/gid 0 и пустые имена
владельцев, права 0755 каталогам и исполняемым и 0644 остальным, время
2020-01-01 UTC, gzip без имени и времени файла в потоке. Поэтому sha256
одинаков на любой ОС и не зависит от сборщика — bsdtar и GNU tar по-разному
набивают поля заголовка. Распаковка — обычным `tar -xzf`.
