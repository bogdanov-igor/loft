# tz-elicit — вопросы к запросу

Используй, когда запрос на ТЗ неполный, а он почти всегда неполный:
прежде чем писать, собери недостающее. Не по одному вопросу — пачкой.

## Порядок

1. Определи тип задачи и возьми банк из `banks.md` (рядом с этим
   скиллом): интеграция / миграция / UI-UX / функциональность / баг /
   общее. Смешанный тип — объедини банки. Ответы записываются в
   требования по шаблонам из `templates.md`.
2. Вычеркни то, на что запрос и корпус уже отвечают: `scout` по wiki и
   spec — возможно, половина ответов уже написана.
3. Оставшиеся раздели на **критичные** (без ответа ТЗ будет неверным) и
   **уточняющие** (без ответа будет допущение).
4. Задай владельцу одним сообщением, сгруппировав по темам. Где можно,
   предлагай варианты ответа: выбрать проще, чем формулировать.
5. Без ответа в этой сессии: критичные → `QUESTIONS.md` с планом
   продолжения и в `questions` паспорта, работа по ним паркуется;
   уточняющие → строка в `assumptions` паспорта: что принято и что это
   подтвердит.
6. Результат — короткий бриф (цель, скоуп, не-скоуп, ограничения,
   критерии приёмки) в `source` паспорта будущего документа или в
   `stages/NNN/brief.md`, если работа большая. В чистовик бриф не
   попадает.

## Правила

- Порядок обращения за ответом: `scout` по корпусу, собственная голова,
  и только потом владелец. Каждый вопрос стоит ему времени.
- Ответы владельца — запись в `spec/решения.md` (дата, вопрос, решение)
  и ссылка в `decisions` паспорта: дата и автор нужны реестру, а не
  читателю.
- Банки — стартовая точка, не потолок: специфичные для проекта вопросы
  добавляй по месту, повторяющиеся — в банк проекта
  (`spec/_STRUCTURE.md`, секция «Вопросы»), и предложи внести в ядро.
