# tz-audit — аудит документации

Используй для приёмки чужого ТЗ, ревизии своего перед сдачей,
периодической проверки корпуса и входного анализа нового проекта
(«что нам досталось»).

## Оси проверки

1. **Полнота** — против `spec/_STRUCTURE.md` или профиля из
   `memory/structures/`: какие обязательные разделы пусты или
   отсутствуют, у каких требований нет критериев приёмки.
2. **Противоречия** — внутри документа; между документом и корпусом
   (глоссарий, соседние ТЗ, wiki); дубли, описывающие одно по-разному;
   разнобой имён одной системы (синонимы вида ИСОБ/ISOB/OB) — сверь
   grep'ом по корпусу против канонического имени из глоссария.
3. **Целостность** — skill `link-check`: битые `[[wikilinks]]`,
   `![[embeds]]`, относительные ссылки, страницы-сироты.
4. **Обоснованность** — утверждения, которых нет ни в источниках
   `based_on`, ни в `assumptions` паспорта; «висящие» открытые вопросы,
   которых нет в `QUESTIONS.md`.
5. **Актуальность** — расхождение с источником истины: дата снапшота
   `wiki/` против живого Confluence, версии API и систем в тексте против
   текущих, «планируется» с прошедшей датой.
6. **Гигиена** — секреты и внутренние адреса открытым текстом (IP,
   хосты, учётки), мусорные дубли файлов.
7. **Читаемость и голос** — против секции «Голос» профиля и
   самопроверки на воду (`tz-elicit/templates.md`): действует ли
   читатель по документу, не открывая других файлов. Служебное в
   чистовике — это дефект.

## Отчёт

Только таблица: документ (или раздел, для одиночного дока) × ось даёт
🟢 ок / 🟡 замечания / 🔴 блокер и одну строку сути на клетку с
замечанием. Прозы вокруг таблицы нет.

- Для корпуса задействуй `stage`: параллельные `scout`'ы по доменам,
  таблица в `stages/NNN-audit-<slug>/report.md`.
- Для одиночного документа таблица идёт в ответе владельцу.

Находки — это строки в `BACKLOG.md`, ровно в формате очереди:

```text
- P1 | документ | что не так | ev:путь:строка | src:audit-NNN
```

`NNN` — это номер stage. Аудит вне stage помечается
`src:audit-ГГГГ-ММ-ДД`.

## Правила

- Каждая находка несёт свидетельство `ev:путь:строка`. Без него находка
  не публикуется.
- Прежде чем писать находку, проверь `BACKLOG.md`: такая уже может быть
  открыта.
- Пока открыто 20+ находок аудита, закрывай их, новый аудит не начинай.
- Аудит не чинит: найденное уходит в очередь, исправления идут
  отдельной работой (мелкие сразу, большие — `stage`).
