# knowledge-map — карта корпуса

Корпус в сотни страниц целиком не читается ни разу: это порядка миллиона
токенов. Векторного поиска ядро не возит, вместо него работает карта.
`wiki/_KNOWLEDGE-MAP.md` — навигатор корпуса: по нему видно, в каком
домене лежит ответ, и дальше домен читается целиком.

Страница, у которой нет строки в карте, для `scout`'а не существует —
поэтому карта покрывает корпус целиком, а не только интересное.

## Что строится

`wiki/_KNOWLEDGE-MAP.md` (файл без `confluence_id` — конвертер его не
трогает). Шапка: дата снапшота из `wiki/.space.json`, число доменов и
страниц, пометка «генерируется скиллом knowledge-map; факты сверяй по
[[ссылкам]] — карта навигатор, не источник истины». Дальше секция на
домен:

```markdown
## <Домен>
**Что это:** 2-3 предложения.
**Вход:** [[главная страница домена]]
**Ключевое:** методы / системы / термины — списком, каждое со ссылкой.
**Читать первым:** 3-7 страниц в порядке погружения, [[wikilinks]].

**Страницы:**
- [[страница]] — одна строка, что там
- [[страница]] — одна строка, что там
```

Строка на страницу — весь смысл файла: по ней решают, открывать страницу
или нет. Она описывает содержание («матрица прав кассира и контролёра, с
исключениями по филиалам»), а не пересказывает заголовок («страница про
права»). Карта на 300 страниц — это ~300 строк: один Read, дальше чтение
идёт прицельно.

## Первый синтез — работа уровня `stage`

Цель: каждая страница корпуса названа ровно один раз, в своём домене, и
по строке понятно, зачем её открывать.

Ограничения:

- домены — из дерева `wiki/.pagemap.json`: страницы верхнего уровня и
  крупные ветки, ~8–15 доменов. Спорную нарезку покажи владельцу в
  `brief.md` стадии до синтеза;
- домен читает параллельный `scout` и возвращает готовую секцию с
  фактами и ссылками; домен больше ~50 страниц делится между двумя
  scout'ами по подветкам; главное окно только сводит и само страницы не
  читает — иначе первый же домен съедает окно;
- терминология единообразится по глоссарию проекта;
- домен без внятной темы честно получает «раздел-свалка, N страниц без
  общей темы» — это находка для `tz-audit`, а не повод сочинять.

Как проверить:

- число строк-страниц сходится с числом страниц в `wiki/`: страница без
  строки — дыра, через которую разведка её не увидит;
- `link-check` зелёный: карта — самый связанный файл корпуса, битая
  ссылка здесь стоит дорого;
- вердикт `verifier` выборочно по 2-3 доменам: «Вход» существует,
  «Ключевое» подтверждается страницами, строки-описания соответствуют
  содержанию открытых страниц.

## Обновление — этим карта и жива

Повторная конвертация (`ingest-confluence`) кладёт рядом отчёт
`wiki/_CHANGES-<дата>.md` — добавлено, изменено, перемещено, удалено; то
же машинно в `wiki/.ingest.json`. По нему:

- определи задетые домены по путям изменённых страниц;
- пересинтезируй только их — `scout` на домен; остальные секции не
  трогаются байт-в-байт;
- добавленные страницы получают строку в своём домене, удалённые уходят
  из всех секций (`link-check` подскажет, где битое);
- обнови дату снапшота в шапке.

Обновление задетых доменов — обычная работа, не `stage`: критерии те же,
что и в первый раз, договариваться заново не о чем. Полный пересинтез —
только по явному запросу владельца.

## Кто ею пользуется

- `scout` — стартовая точка любой разведки по корпусу: сначала секция
  домена, потом страницы этого домена целиком.
- `tz-write` — секция домена говорит, какие страницы открывать целиком
  под `based_on`.
- `tz-audit` — полнота корпуса: чего нет вовсе, какие домены держатся на
  одной странице, где темы дублируются между доменами.

## Правила

- Карта — не источник истины: факт в ТЗ цитируется со страницы-источника.
  Ссылка нужна, чтобы страницу открыть, а не чтобы её пересказать.
- Ручные правки карты умрут при пересинтезе секции — постоянные
  комментарии живут в `spec/` со ссылкой на домен.
