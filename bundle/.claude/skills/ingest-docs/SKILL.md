# ingest-docs — входящие файлы

## Цель

Файл из `inbox/` становится страницей корпуса, у которой видно
происхождение, а оригинал уезжает в `inbox/done/`: непрочитанное видно в
файловой системе, а не в памяти агента. Возврат заказчика с правками
сюда не идёт — обычная конвертация молча теряет track changes и
комментарии, для него есть `review-intake`.

## Конвертация

docx — детерминированно, путь ровно один:

```sh
# из каталога spec/: медиа ляжет в spec/assets/media/, и ссылки в
# документе будут корректны относительно него
cd spec && pandoc -f docx -t gfm --wrap=none --extract-media=assets \
  "../inbox/<файл>.docx" -o "<слаг>.md"
```

`.doc` pandoc не читает — сконвертируй в `.docx`
(`soffice --headless --convert-to docx`, LibreOffice) или попроси
владельца пересохранить. Одиночная html-страница —
`pandoc -f html -t gfm --wrap=none`, дальше как docx; целая выгрузка
Confluence — это skill `ingest-confluence`.

pdf и картинки — единственное место ingest'а, где работает модель, а не
скрипт. Поэтому результат называется конспектом и помечается им:

```markdown
> Конспект. Оригинал: inbox/done/<файл>.pdf (N страниц, конспект от
> <дата>). Числа и формулировки при использовании сверять с оригиналом.
```

Конспект пишется по всему оригиналу, а не по первым страницам: Read
берёт ~20 страниц за вызов, большой pdf — частями или параллельными
scout'ами, готовое сверяется с оригиналом до последней страницы. Таблицы
переноси как GFM, у ключевых фактов ставь страницу оригинала (`стр. 12`).
Картинка ложится в `assets/`, в документ — `![[файл.png]]` с подписью:
что изображено, откуда, от какой даты; нужна живая диаграмма — перерисуй
её в `mermaid` рядом с embed'ом, пометив «перерисовано с [[оригинала]]»:
источником истины остаётся картинка. Результат кладётся в `spec/` по
раскладке проекта или туда, куда указал владелец.

## Паспорт результата

```yaml
source: inbox/done/<файл>.docx
ingested: <дата>
```

`source:` — простой текст, не `[[ссылка]]` и не `[текст](путь)`:
оригиналы лежат вне корпуса, `link-check` их не видит и посчитает такую
ссылку битой. Путь пишется сразу конечным — тем, по которому файл будет
лежать после переезда. `based_on` конвертации не нужен: оригинал и есть
её источник. Секреты и внутренние адреса в корпус не переносятся —
вместо них `{{secret:KEY}}` или плейсхолдер `{ИМЯ_СИСТЕМЫ}`; оригинал в
`inbox/` остаётся как есть.

## Образец

Владелец сказал «возьми за основу», «это шаблон», «референс» → md
кладётся в `spec/_reference/<имя>.md`, в паспорте — `role: reference`.
Дальше профиль: чужая структура — `tz-adapt`, своя — `spec-bootstrap`;
обновляются секции «Структура» и «Голос». Образец, не дошедший до
профиля, не влияет ни на один документ, а без слова владельца в
`_reference/` не попадает ничего — иначе образцом становится любой
присланный файл.

## После конвертации

Конвертация готова и `link-check` зелёный → оригинал переезжает в
`inbox/done/` под тем же именем; переименовывать нельзя, на это имя
указывает `source:`. Что лежит в `inbox/` мимо `done/` — ещё не
потреблено, и это единственный признак: «я это уже читал» сессию не
переживёт.

Владелец просил встроить файл в конкретный документ → строка в
`BACKLOG.md`, она закрывается, когда `spec/<слаг>.md` попал в `based_on`
этого документа:

```text
- P1 | <документ> | встроить <слаг>.md | ev:spec/<слаг>.md | src:владелец
```

Без такой просьбы конвертация строки не порождает: очередь остаётся
очередью работы, а не журналом приёмки.

## Как проверить

- таблицы и картинки конвертации просмотрены глазами;
- у результата есть `source:`, и он ведёт на существующий файл;
- `link-check` зелёный, страница не сирота — связана `[[wikilink]]`-ами
  с корпусом;
- в `inbox/` не осталось обработанных оригиналов.

Пачка файлов → по файлу на параллельного сабагента; итоги сведи в один
список «что пришло → где лежит».
