# Loft — роадмап (порезан 2026-07-15)

## Правило границы (главный итог обсуждения)

**Скрипт в ядре loft — только детерминированный конвертер данных
(вход → выход): convert.py (внутри tablemd.py, общий с fix_tables.py),
make_index.py, fix_tables.py, link_check.py, export_pdf.py, sweep.sh. Всё.**
Проверки смысла (терминология, полнота, санитария, трассировка, голос) —
УКАЗАНИЯ агентам в скиллах: агент читает скилл и делает это сам.
Функции с состоянием, историей и UI (git/дифф/версии/граф-экран/
канбан) — фичи Specweave v2, не ядра. Никаких эмбеддингов, векторов,
MCP, демонов, расписаний — никогда.

## Решения 1.3.0 (2026-09-09)

Релиз не про фичи, а про то, для кого пишется документ; что именно сделано —
в CHANGELOG. Здесь только решения, которые связывают руки дальше.

- **RAG и векторный поиск — не делаем.** Чанк без контекста и оговорок в ТЗ
  дороже лишнего чтения; вместо индекса — карта корпуса плюс чтение домена
  целиком scout'ом на Sonnet с окном 1M. Могила specos остаётся закрытой.
- **NotebookLM — только односторонне.** Пакет md/PDF туда (deliver-pdf
  `--md`/`--bundle`), обратно через inbox/. MCP-серверов и библиотек на
  cookies в ядре нет: ломаются тихо и уносят доверие к содержимому ноутбука.
- **Plugin-упаковка отложена.** Блокер технический: плагин не доставляет
  CLAUDE.md, а скиллы внутри плагина получают префикс в имени — установка
  становится двухступенчатой вместо одной команды.
- **.claude/rules с paths не используем** — не переживают compact, а правило,
  исчезающее в середине сессии, хуже отсутствующего.
- **Точное число тестов в README — не витрина.** Цифра дрейфует каждый
  релиз, поэтому в README «более 500 самотестов», а точное число живёт в
  CHANGELOG и в прогоне.

## Loft — что делаем

- [x] **Экспорт в PDF** (1.0.0) — единственный экспортный формат ядра:
  скилл deliver-pdf, резолв [[wikilinks]] в текст, mermaid — как получится
  без тяжёлых зависимостей. docx/doc не делаем; Confluence-экспорт тоже:
  .md в Confluence импортирую сам, в скилле только указание проверить
  ссылки и картинки перед импортом.
- [x] **review-intake** (1.0.0) — входящая труба, не экспорт:
  `pandoc --track-changes=all` для правленого docx (без него правки молча
  схлопываются — риск №1) и таблица «правка → принять/отклонить/вопрос».
  Пара правок — без церемонии, полный раунд — stage. С 1.3.0 правки текстом
  из чата и Confluence — такой же штатный вход.
- [x] **Указания в скиллах вместо скриптов** — глоссарий, линт имён,
  светофор и REQ-трассировка живут формулировками в tz-audit (синонимы
  одной системы: ИСОБ/ISOB/OB), tz-write (термин не из глоссария — сначала
  в глоссарий) и verifier (санитария: IP, хосты, токены в тексте). Агенты
  делают это чтением и grep'ом по ходу работы, новых скриптов не появилось.
- [x] **templates.md в tz-elicit** (1.1.0) — банк формулировок требований:
  EARS по-русски, user story с Given/When/Then, НФТ-таблица. Это данные для
  агента, не код. В 1.3.0 добавлены раздел «Голос» и самопроверка на воду.
- [x] **knowledge-map** (1.1.0) — воспроизводимая карта корпуса скиллом
  уровня stage, без инфраструктуры. С 1.3.0 обязательна и покрывает корпус
  строкой на страницу.
- [x] **Конвертер: --unroll-pre** (1.1.0) — JSON-таблицы разворачиваются в
  GFM плюс код-фенсы после таблицы, опциональным флагом.
- [x] **Документ для читателя, а не для судьи** (1.3.0) — паспорт во
  frontmatter, чистовик без служебных маркеров, verifier с читателем первой
  осью и списком «убрать».
- [ ] **Конвертер: человекочитаемые имена вложений** — переименование
  `2923549_*.pdf` по алиасам с переписью ссылок; внутри существующих
  детерминированных скриптов, по запросу.
- [ ] **Слой задач (Jira)** — в раскладке корпуса его нет и пока не
  планируется: задачи живут в трекере, ядро ведёт документы. Вернуться,
  если появится работа, где ТЗ и задачи расходятся молча.
- [ ] **Эталонные запросы для ручного эвала ядра** — типовые задания, чтобы
  правки контракта и скиллов сверять не на глаз. Ждут образцов владельца:
  набор без его документов и его голоса проверял бы не то.
- [ ] **Из keel 1.8.0** — два хука, у каждого свой инцидент: `verdict-guard`
  (вердикт verifier'а в отчёте stage без agent id — отказ в записи) и
  `recompact` (после сжатия контекста хук возвращает стадию, claim'ы и
  гейты). WIP-лимит аудита и claim до начала работы уже в контракте.
- [ ] **Plugin-упаковка** — второй пользователь появился, блокер прежний
  (см. решения 1.3.0).

## Specweave v2 — куда переехали идеи (заморожен, копилка фич)

- Git, дифф, история версий документа, «машина времени», бэкапы — поверх
  git, как и решено раньше.
- Терминология, светофор и REQ-матрица как отдельные функции с UI.
- Граф связей (экран), канбан BACKLOG, карточки-опросники tz-elicit.
- Статус проекта или портфеля как экран.
- REST-синхронизация с Confluence — если вообще делать, то тут.

## Отклонено навсегда

- Экспорт в docx/doc и в Confluence storage format / REST PUT.
- Текстовые сайдкары вложений, переименование через отдельный тул —
  агент открывает PDF или диаграмму глазами, когда нужно.
- reqtrace/spec_status/term_lint как скрипты-гейты.
- Scheduled routines, auto-memory сабагентов.
- SessionStart-хуки-ритуалы: сводка, план или статус, печатаемые в каждую
  сессию, — всё, что печатает хук, попадает в контекст каждый раз. Тихий
  update-check остаётся единственным SessionStart-хуком ядра: он молчит,
  пока новой версии нет, и счастливый путь стоит ноль токенов.
- Эмбеддинги, векторы, свой MCP и RAG над корпусом — могила specos, не
  возвращаемся.

Output styles из этого списка вычеркнуты в 1.3.0: стиль ничего не печатает
и не грузится сверх контракта, он снимает чужие установки про код и
включается владельцем вручную.
